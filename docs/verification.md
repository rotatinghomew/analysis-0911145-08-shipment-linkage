# 运行与验证

`python -m unittest discover -s tests -v` 覆盖三部分：旧业务预览与资料校验、新分析消费接口的 HTTP 传输、以及条件推断本身的可核对计算。`python -m app.demo` 临时启动服务，通过消费端走真实 HTTP，打印旧业务预览、新资料的描述输出，以及每个分析资料的诊断结果、撤除一项证据后的敏感性对照、以及收紧预算后的补验清单。

## 推断正确性

`tests/test_inference.py` 不依赖资料名，用小型合成图直接核对算法：

- 链式图与多父节点图的后验与手算一致；
- 区间条件概率的后验界限等于可行参数集合上的极值，并检查各状态界限不保证相加为一；
- 同一上游原因下的两条观测不按独立选票处理；
- 零支持证据返回 `incompatible` 且 `posterior`、`test_value` 为 `null`，并给出最小复核证据集；
- 图的校验错误与证据零支持通过 `compatibility.reason` 区分；
- 补验价值等于决策损失下降减去成本（含完全信息补验的解析值），超预算项被剔除；
- 撤除证据后报告前后差异，且 `snapshot`、`graph_version`、证据来源保持。

`RUN_ACCEPTANCE=1 python -m unittest tests.test_acceptance -v` 现在默认启用，验证经真实 HTTP 的字段、区间、敏感性选项与错误输入。它只承担契约回归，算法正确性以上述小型核对为准；两者都不构成对机理图本身是否正确的外部证明。

## 规模与时间

资料规模在本地枚举可行条件概率完成；`interval` 案例有 256 个完成，单次分析约 0.1 秒，全部演示小样本在 90 秒内结束。超过 `MAX_WORK` 的请求返回 `graph_invalid`，不会静默降级为抽样近似。
